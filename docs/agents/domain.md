# 도메인 문서

엔지니어링 스킬이 코드베이스를 탐색할 때 이 저장소의 도메인 문서를 어떻게 읽어야 하는지 정리한다. 이 저장소는 **single-context** 레이아웃이다.

## 탐색 전에 읽을 것

- 저장소 루트의 **`GLOSSARY.md`**
- **`docs/adr/`**: 작업하려는 영역에 관련된 ADR을 읽는다.

이 파일들이 없으면 **조용히 진행한다**. 없다는 사실을 지적하거나 미리 만들자고 제안하지 않는다. `/domain-modeling` 스킬(`/grill-with-docs`, `/improve-codebase-architecture`를 통해 호출됨)이 용어나 결정이 실제로 정해질 때 필요에 따라 만든다.

## 파일 구조

```
/
├── GLOSSARY.md
├── docs/adr/
│   ├── 0001-example-decision.md
│   └── 0002-another-decision.md
└── src/
```

## 용어집의 어휘를 사용할 것

산출물(이슈 제목, 리팩터링 제안, 가설, 테스트 이름)에서 도메인 개념을 언급할 때는 `GLOSSARY.md`에 정의된 용어를 쓴다. 용어집이 명시적으로 피하는 동의어로 바꾸지 않는다.

필요한 개념이 아직 용어집에 없다면 신호로 받아들인다: 프로젝트가 쓰지 않는 말을 만들어내고 있거나(재고할 것), 실제로 빈틈이 있는 것이다(`/domain-modeling`에 메모해 둘 것).

## ADR 충돌은 드러낼 것

산출물이 기존 ADR과 모순되면 조용히 덮어쓰지 말고 명시적으로 드러낸다:

> _ADR-0007(event-sourced orders)과 모순되지만, …때문에 다시 논의할 가치가 있음_
