# 링크 불변성을 API·저장소 코드·DB 세 겹에서 지킨다

링크는 발급 후 수정·삭제·만료·재사용되지 않아야 하고, 과제는 화면이 아니라 서버에서 변경을 거부하라고 요구한다. 그래서 API는 생성만 제공하고 `/api/links/{n}`의 `PUT`/`PATCH`/`DELETE`는 405로 명시적으로 거부하며, 저장소 코드에는 `insert`와 `find`만 두고, DB에는 `BEFORE UPDATE OR DELETE` 트리거로 예외를 낸다. 트리거가 있으므로 SQL을 직접 실행해도 기존 링크를 바꿀 수 없다.

## Consequences

- 같은 원본 URL을 다시 입력하면 항상 새 단축 번호를 발급한다. 기존 링크를 찾아 돌려주는 규칙은 원본 URL에 UNIQUE 제약(긴 URL은 해시 컬럼)과 동시 입력 경쟁 처리가 필요해서 택하지 않았다.
- 단축 번호는 `BIGINT GENERATED ALWAYS AS IDENTITY` 기본키로 발급한다. 번호에 구멍이 생길 수 있지만 같은 번호가 두 번 발급되지는 않는다.
