# 스펙: 숫자형 단축 URL 서비스

## Problem Statement

긴 URL은 공유하기 불편하다. 사용자는 회원가입이나 로그인 없이 긴 URL을 짧은 주소로 바꾸고 싶다. 그 주소는 숫자로만 되어 있어 읽고 말하기 쉬워야 한다. 한번 공유한 단축 주소는 시간이 지나도, 서버가 재시작되거나 재배포되어도 같은 원본 URL로 이동해야 한다. 누구도 이미 공유된 단축 주소의 목적지를 바꿔치기할 수 없어야 한다.

## Solution

누구나 쓸 수 있는 웹 화면을 제공한다. 사용자가 원본 URL을 입력하고 생성 버튼을 누르면 서버가 새 링크를 만들고 단축 번호를 발급한다. 화면은 `https://<서비스 도메인>/<단축 번호>` 형태의 단축 주소를 보여 주고, 복사 버튼을 제공한다. 누군가 단축 주소에 접속하면 서버가 HTTP 301로 원본 URL에 이동시킨다. 링크는 DB에 영구 저장되며 생성 후에는 수정·삭제·만료되지 않는다.

공개 접점은 Cloudflare Worker 하나다. Worker가 웹 화면을 제공하고, API와 숫자 경로는 Railway의 Rust 백엔드로 프록시한다. 링크는 Railway Postgres에 저장한다. 전체 운영 비용은 0원이다.

## User Stories

### 생성

1. 방문자로서, 회원가입·로그인 없이 URL 입력 화면을 쓰고 싶다. 그래야 바로 단축 주소를 만들 수 있다.
2. 방문자로서, 시크릿 창이나 처음 쓰는 브라우저에서도 생성 기능을 쓰고 싶다. 그래야 어떤 환경에서도 같은 경험을 얻는다.
3. 방문자로서, 원본 URL을 입력하고 생성 버튼을 누르면 단축 주소를 받고 싶다. 그래야 긴 URL 대신 짧은 주소를 공유할 수 있다.
4. 방문자로서, 단축 주소가 `/123`처럼 숫자로만 되어 있기를 원한다. 그래야 읽고 받아 적기 쉽다.
5. 방문자로서, 생성된 단축 주소를 복사 버튼 하나로 클립보드에 복사하고 싶다. 그래야 직접 선택해서 복사하는 수고가 없다.
6. 방문자로서, 복사가 성공했다는 표시를 보고 싶다. 그래야 실제로 복사되었는지 안다.
7. 방문자로서, 생성 중에는 버튼이 진행 중 상태로 바뀌기를 원한다. 그래야 중복 클릭을 하지 않는다.
8. 방문자로서, 같은 원본 URL을 다시 입력하면 새 단축 주소를 받고 싶다. 그래야 규칙이 단순하고 예측 가능하다.
9. 방문자로서, 생성 후 다른 URL을 이어서 단축하고 싶다. 그래야 페이지를 새로고침하지 않고 여러 개를 만든다.

### 검증

10. 방문자로서, `http://`나 `https://`가 아닌 주소(예: `ftp://`, `javascript:`)를 입력하면 이유가 담긴 오류 메시지를 보고 싶다. 그래야 무엇을 고쳐야 하는지 안다.
11. 방문자로서, host가 없는 주소나 형식이 깨진 주소를 입력하면 오류 메시지를 보고 싶다. 그래야 잘못 붙여 넣은 값을 알아챈다.
12. 방문자로서, 2048자를 넘는 주소를 입력하면 길이 초과 오류를 보고 싶다. 그래야 제한을 안다.
13. 방문자로서, 이 서비스의 단축 주소를 다시 단축하려 하면 거부 메시지를 보고 싶다. 그래야 이동이 꼬리를 무는 링크가 생기지 않는다.
14. 운영자로서, 화면 검증을 우회한 직접 API 요청도 서버가 같은 규칙으로 거부하기를 원한다. 그래야 잘못된 링크가 저장되지 않는다.
15. 방문자로서, 입력값 앞뒤의 공백은 무시되기를 원한다. 그래야 복사 실수로 오류가 나지 않는다.

### 이동

16. 단축 주소를 받은 사람으로서, 단축 주소를 열면 곧바로 원본 URL로 이동하고 싶다. 그래야 중간 페이지 없이 목적지에 간다.
17. 단축 주소를 받은 사람으로서, 원본 URL의 경로·쿼리 문자열·프래그먼트(`#...`)가 그대로 유지되기를 원한다. 그래야 정확한 위치에 도착한다.
18. 단축 주소를 받은 사람으로서, 생성자와 다른 브라우저에서도 이동이 되기를 원한다. 그래야 누구에게든 공유할 수 있다.
19. 단축 주소를 받은 사람으로서, 존재하지 않는 번호를 열면 알아볼 수 있는 404 안내를 보고 싶다. 그래야 주소가 틀렸음을 안다.
20. 단축 주소를 받은 사람으로서, 404 안내에서 새 단축 주소를 만드는 화면으로 돌아가는 링크를 원한다. 그래야 막다른 곳에 머물지 않는다.
21. 운영자로서, `/0`, `/0123`, `i64` 범위를 넘는 숫자는 404로 처리되기를 원한다. 그래야 링크 하나에 단축 주소가 정확히 하나만 존재한다.
22. 운영자로서, 이동이 HTTP 301 응답이기를 원한다. 그래야 JavaScript 없이도, 검색 엔진과 메신저 미리보기에서도 이동이 동작한다.

### 불변성

23. 단축 주소를 공유한 사람으로서, 누구도 내 링크의 원본 URL을 바꾸지 못하기를 원한다. 그래야 공유한 주소가 엉뚱한 곳으로 가지 않는다.
24. 단축 주소를 공유한 사람으로서, 링크가 삭제되거나 만료되지 않기를 원한다. 그래야 오래전에 공유한 주소도 계속 동작한다.
25. 운영자로서, 이미 발급된 단축 번호가 다른 원본 URL에 다시 쓰이지 않기를 원한다. 그래야 번호와 목적지의 관계가 영구적이다.
26. 운영자로서, 링크 변경 요청(`PUT`/`PATCH`/`DELETE`)을 서버가 405로 거부하기를 원한다. 그래야 화면 밖의 요청으로도 변경할 수 없다.
27. 운영자로서, DB에 직접 SQL로 수정·삭제를 시도해도 거부되기를 원한다. 그래야 코드 실수나 수동 작업으로 링크가 바뀌지 않는다.
28. 방문자로서, 화면에서 수정·삭제 버튼을 볼 수 없기를 원한다. 그래야 불가능한 동작을 시도하지 않는다.

### 동시성과 영속성

29. 운영자로서, 서로 다른 URL에 대한 생성 요청이 동시에 와도 같은 번호가 두 번 발급되지 않기를 원한다. 그래야 기존 링크가 덮어써지지 않는다.
30. 운영자로서, 서버를 재시작하거나 재배포해도 기존 단축 주소가 같은 원본 URL로 이동하기를 원한다. 그래야 배포가 링크를 깨지 않는다.
31. 운영자로서, 서버가 처음 시작될 때 스키마가 자동으로 준비되기를 원한다. 그래야 DB를 손으로 설정하지 않아도 된다.

### 배포와 운영

32. 운영자로서, 공개 HTTPS 주소 하나에서 화면·생성·이동이 모두 동작하기를 원한다. 그래야 사용자가 하나의 도메인만 안다.
33. 운영자로서, 브라우저가 같은 출처로만 요청하기를 원한다. 그래야 CORS 설정과 백엔드 주소 노출이 필요 없다.
34. 운영자로서, DB 비밀번호와 백엔드 주소가 브라우저 코드와 저장소에 들어가지 않기를 원한다. 그래야 비밀 값이 유출되지 않는다.
35. 운영자로서, 필요한 환경변수 이름을 `.env.example`에서 확인하고 싶다. 그래야 로컬과 배포 환경을 빠르게 설정한다.
36. 운영자로서, 운영 비용이 0원이기를 원한다. 그래야 과제 제출에 돈이 들지 않는다.
37. 운영자로서, 백엔드가 유휴 시간에 잠들어 크레딧을 아끼기를 원한다. 그래야 Trial 크레딧으로 제출 기간을 버틴다.
38. 평가자로서, README 최상단의 `## 배포 URL` 섹션에서 서비스 URL·테스트 단축 URL·테스트 원본 URL을 확인하고 싶다. 그래야 바로 동작을 확인할 수 있다.
39. 평가자로서, README에서 로컬 실행, DB 준비, 환경변수, 배포·라우팅, 번호 발급·중복 방지·불변성 설계, 확인 시나리오 재현 방법을 읽고 싶다. 그래야 소스만 보고도 설계를 평가할 수 있다.

## Implementation Decisions

### 구성

- Dioxus 풀스택(Rust) 단일 크레이트로 만든다. `web` 기능은 브라우저 화면(WASM)을, `server` 기능은 Railway에서 도는 axum 기반 백엔드를 빌드한다.
- 공개 접점은 Cloudflare Worker 하나다(ADR-0001). Worker는 Static Assets로 Dioxus 웹 번들을 제공하고, `/api/*`와 `/^[1-9][0-9]*$/`를 비롯한 숫자 경로를 Railway 백엔드로 프록시한다. 경로 판정은 "숫자로만 된 단일 세그먼트"면 모두 백엔드로 보낸다. `/0`, `/0123` 같은 비정규형 판정은 백엔드가 한다. 백엔드의 이동 응답은 `redirect: "manual"`로 받아 그대로 클라이언트에 전달한다.
- 백엔드 주소는 Worker 환경변수(`BACKEND_ORIGIN`)로만 받는다.
- 화면은 Worker가 정적으로 제공하는 클라이언트 렌더링 페이지다. 서버 함수 호출은 같은 출처의 `/api/*`로 나가도록 클라이언트의 서버 URL을 설정한다.

### 모듈

- **링크 저장소 (Link Repository)**: 인터페이스는 `insert(원본 URL) -> 링크`와 `find(단축 번호) -> Option<링크>` 두 개뿐이다. 수정·삭제 함수는 만들지 않는다. `sqlx` + Postgres를 쓰고, 커넥션 풀은 최대 3개다.
- **원본 URL 검증 (Original URL Validation)**: 입력 문자열과 서비스 공개 주소를 받아 정규화된 원본 URL이나 검증 오류를 돌려주는 순수 함수다. 규칙은 다음과 같다.
  - 앞뒤 공백을 제거한다.
  - `url` 크레이트로 파싱한다.
  - scheme이 `http`/`https`여야 한다.
  - host가 있어야 한다.
  - 직렬화한 결과가 2048자 이하여야 한다.
  - host가 `PUBLIC_BASE_URL`의 host와 달라야 한다.
  - 저장하는 값은 직렬화한 문자열이다.
- **단축 번호 파싱 (Short Number Parsing)**: 경로 세그먼트를 정규형 단축 번호로 바꾸는 순수 함수다. 1 이상이고, 앞자리에 0이 없고, `i64` 범위 안이어야 한다. 실패하면 "없음"으로 취급해 404로 이어진다.
- **HTTP 라우터**: 다음 경로를 처리한다.
  - 링크 생성: 서버 함수 또는 `POST /api/links`
  - 이동: `GET /{세그먼트}`
  - 변경 거부: `PUT`/`PATCH`/`DELETE /api/links/{n}`에 405
  - 헬스 체크: `GET /api/health`
- **화면**: 원본 URL 입력, 생성 버튼(진행 중 상태 포함), 결과 단축 주소 표시, 복사 버튼(성공 표시 포함), 오류 메시지로 구성한다. 수정·삭제 UI는 없다.
- **404 안내 페이지**: 백엔드가 직접 렌더링하는 간단한 HTML이다. 상태 코드는 404이고, 생성 화면으로 돌아가는 링크를 둔다.

### API 계약

- **생성**: 요청은 `{ "url": "<원본 URL>" }`이다.
  - 성공하면 `201`과 `{ "number": <i64>, "short_url": "<PUBLIC_BASE_URL>/<number>", "original_url": "<정규화된 원본 URL>" }`를 응답한다.
  - 검증에 실패하면 `400`과 `{ "error": "<사람이 읽을 수 있는 메시지>" }`를 응답한다.
- **이동**: `GET /{n}`이 정규형이고 링크가 있으면 `301`과 `Location: <원본 URL>`을 응답한다. 그 밖의 경우는 `404` 안내 HTML을 응답한다.
- **변경 시도**: `PUT`/`PATCH`/`DELETE /api/links/{n}`은 `405`와 `Allow` 헤더, 그리고 불변성을 설명하는 오류 본문을 응답한다. 링크 존재 여부와 상관없이 항상 같다.

### 스키마

- `links` 테이블은 다음 컬럼으로 구성한다.
  - `number BIGINT GENERATED ALWAYS AS IDENTITY PRIMARY KEY`
  - `original_url TEXT NOT NULL`, 길이 2048 이하 `CHECK`
  - `created_at TIMESTAMPTZ NOT NULL DEFAULT now()`
- 단축 번호는 오직 identity로만 발급한다. 애플리케이션은 번호를 지정하지 않는다. `GENERATED ALWAYS`이므로 번호를 지정한 INSERT도 거부된다.
- `BEFORE UPDATE OR DELETE` 행 트리거와 `BEFORE TRUNCATE` 문장 트리거가 예외를 발생시킨다(ADR-0002).
- 같은 원본 URL에 UNIQUE 제약을 두지 않는다. 매번 새 링크를 발급한다.
- 마이그레이션은 서버 시작 시 `sqlx::migrate!`로 적용한다.

### 환경변수

| 위치 | 변수 |
| --- | --- |
| 백엔드 | `DATABASE_URL`, `PUBLIC_BASE_URL`, `PORT`(Railway 주입), `IP` 또는 바인드 주소 |
| Worker | `BACKEND_ORIGIN` |

실제 값은 저장소에 넣지 않고, `.env.example`에 이름만 둔다.

### 배포

- **Railway**: 멀티스테이지 `Dockerfile`(cargo-chef 캐시, 최종 단계는 실행 파일만 담은 작은 이미지)로 빌드한다.
  - `railway.json`(또는 `railway.toml`)에 빌드 방식과 헬스 체크 경로를 적는다.
  - 백엔드는 절전(App Sleeping)을 켜고, Postgres는 상시 켜 둔다.
  - 카드를 등록하지 않는다(ADR-0003).
  - Railway 빌드가 자원 부족으로 실패하면 GitHub Actions 빌드 + GHCR로 전환한다.
- **Cloudflare**: `wrangler.jsonc`에 assets 디렉터리, 프록시 스크립트, `BACKEND_ORIGIN`을 설정한다. 비밀이 아니므로 `vars` 또는 대시보드 변수로 둔다. 공개 주소는 무료 `workers.dev` 서브도메인이다.

## Testing Decisions

- 좋은 테스트는 외부 동작만 검증한다. HTTP 요청을 보내면 상태 코드·헤더·본문이 어떻게 나오는지, DB에 무엇이 남는지를 본다. 내부 함수 호출 순서나 구조체 모양은 검증하지 않는다.
- **경계 1 (주 경계): 백엔드 HTTP 라우터.** 서버가 쓰는 것과 같은 axum `Router`를 프로세스 안에서 `tower::ServiceExt::oneshot`으로 호출한다. 저장소는 실제 로컬 Postgres(`DATABASE_URL`)를 쓴다. 테스트마다 격리된 DB를 쓴다(예: `#[sqlx::test]`). 검증할 시나리오는 다음과 같다.
  - 유효한 URL로 생성하면 201과 단축 번호가 응답되고, 같은 URL로 다시 생성하면 다른 번호가 응답된다.
  - 다음 입력은 400으로 거부된다.
    - `ftp://`, `javascript:`
    - host가 없는 URL
    - 2048자를 넘는 URL
    - 자기 도메인 URL
    - 빈 문자열
  - 이동하면 301이 응답되고, `Location`이 경로·쿼리·프래그먼트를 포함한 원본 URL과 정확히 같다.
  - 다음 요청은 404 안내 HTML을 응답한다.
    - 없는 번호
    - `/0`
    - `/0123`
    - `/99999999999999999999`
  - `PUT`/`PATCH`/`DELETE /api/links/{n}`은 405를 응답하고, 그 뒤의 이동 결과가 그대로다.
  - 서로 다른 URL N개(예: 50개)로 생성 요청을 동시에 보내면, 번호가 모두 다르고 각 번호가 자기 원본 URL로 이동한다.
  - 영속성: 풀과 라우터를 버리고 새로 만들어도(재시작을 흉내 냄) 기존 번호가 같은 원본 URL로 이동한다.
- **경계 2 (보조 경계): DB 스키마.** 같은 테스트 DB에서 다음을 직접 SQL로 실행하고, 모두 실패하며 데이터가 그대로인지 확인한다.
  - `UPDATE links ...`
  - `DELETE FROM links ...`
  - `TRUNCATE links`
  - 번호를 지정한 `INSERT`
- **원본 URL 검증과 단축 번호 파싱**은 경계 1에서 이미 검증된다. 그래서 순수 함수 단위 테스트는 경계 1로 표현하기 번거로운 경계값(정확히 2048자, `i64::MAX`, `i64::MAX + 1`)에만 둔다.
- **자동 테스트를 두지 않는 부분**: Worker 경로 분기와 Dioxus 화면이다. 이 부분은 `npx wrangler deploy --dry-run`과 `dx build --release` 성공, 그리고 배포 후 README의 수동 확인 시나리오로 확인한다.
- **Prior art**: 저장소에 기존 테스트가 없다. 이 스펙의 경계 1 테스트가 이후 테스트의 기준이 된다.
- 검증 명령은 `AGENTS.md`의 "검증 명령" 섹션을 따른다.

## Out of Scope

- 회원가입, 로그인, 사용자별 링크 목록
- 링크 수정, 삭제, 만료, 비활성화
- 사용자 지정 별칭과 영문·랜덤 코드
- 같은 원본 URL에 기존 번호를 돌려주는 중복 제거
- 클릭 수 통계와 분석
- 남용 방지 (rate limit, 피싱·악성 URL 차단 목록)
- 유료 커스텀 도메인과 유료 플랜
- QR 코드 생성
- Worker와 화면의 자동화 테스트
