# 07: 동시 발급과 영속성 검증

**What to build:** 서로 다른 원본 URL로 생성 요청이 동시에 몰려도 단축 번호가 겹치지 않고, 서버가 재시작되어도 기존 단축 주소가 같은 원본 URL로 이동함을 테스트로 보장한다.

**Blocked by:** 02

**Status:** resolved

- [x] 서로 다른 URL 50개를 동시에 생성하면 번호가 모두 다르고, 각 번호가 자기 원본 URL로 이동한다 (경계 1 테스트)
- [x] 풀과 라우터를 버리고 새로 만든 뒤에도 기존 번호가 같은 원본 URL로 이동한다 (경계 1 테스트)
- [x] 같은 원본 URL로 두 번 생성하면 서로 다른 번호가 발급된다

## Comments

- 서브에이전트 생성이 막혀 메인 세션에서 직접 작성했다. 기존 동작을 보장하는 특성 테스트라 처음부터 통과했다 (red 단계 없음).
- 동시성 테스트는 연결 20개짜리 풀과 `JoinSet`으로 50건을 실제로 병렬 실행한다. 재시작은 기존 풀을 닫고 같은 DB에 새 풀로 다시 연결해 흉내 낸다.
